# sbatch_submission — training + metrics + LaTeX table pipeline

Compares 8 methods (`UNet`, `4dvarnet_lstm`, `CM`, `VarCM`, `DynCM`, `VarDynCM`,
`FM`, `DynFM`) on one variable (`GP`, `SIC` or `SSH_GF`), from the notebooks
under `../Notebooks/Notebooks_<XP>/`. The notebooks remain the source of
truth: this directory executes them in a parameterized way via `papermill`,
it does not reimplement the methods.

## Files

| File | Role |
|---|---|
| `methods.yaml` | Registry: notebook per (method, xp), `LOG_DIR`, generative or not, overrides (`COND_MODE`, `SOLVER_TYPE`) |
| `cell_library.py` | Generic splitting of a notebook into setup / data / method blocks (based on cell content, not position) |
| `generate_missing_notebooks.py` | Assembles the missing notebooks (target-xp dataloader + GP reference method code) — **already run**, cf. limitations below |
| `patch_notebook_params.py` | Makes a notebook papermill-parameterizable (`parameters` cell + CSV serialization) — **already run on all 24 notebooks** |
| `run_training.py` | `papermill`s one (xp, method) with `MAX_EPOCHS=2000`, light eval (`N_SAMPLES=1`) |
| `run_metrics.py` | `papermill`s the same notebook, checkpoint reloaded, `N_SAMPLES=50` (generative) / `1` (deterministic) |
| `make_latex_table.py` | Reads the CSVs in `results/<xp>/` and writes `results/<xp>/comparison_table.tex` |
| `submit_train.sbatch` / `submit_metrics.sbatch` | Sequential loop over the 8 methods (Odyssey convention) |

## Usage on the cluster

```bash
sbatch submit_train.sbatch GP          # 8 sequential trainings, 2000 epochs each
sbatch submit_metrics.sbatch GP        # 8 metrics passes (50 members for the 6 generative ones) + LaTeX table
cat results/GP/comparison_table.tex
```

For SIC/SSH_GF, the missing notebooks have already been generated by
`generate_missing_notebooks.py` (SIC: `UNet`, `4dvarnet_lstm`, `VarCM`,
`DynCM`, `VarDynCM`, `DynFM` ; SSH_GF: `VarCM`, `DynCM`, `VarDynCM`, `DynFM`)
— **see the next section before running them in production.**

Dependencies added to `../../environment.yaml`: `papermill`, `nbformat`,
`pandas`, `pyyaml`.

## ⚠️ Known limitations of the 10 generated notebooks (SIC ×6, SSH_GF ×4)

Each generated notebook contains its own "⚠️ ACTION REQUIRED" cell (first
cell after setup) listing the points below for that specific combo.
Overall:

1. **`sigma_max` / `SIGMA_NOISE`**: carried over as-is from the GP notebook
   (physical scale of the `GP`/SPDE variable) — needs to be recalibrated to
   the scale of SIC (≈1.0, cf. the existing `CM_sic` notebook) or SSH_GF
   (≈10, cf. `CM_ssh_gf`) before any production run.
2. **`cond_channels`**: automatically fixed only for the literal
   `UNetConfig(channels=C)` pattern (×2 factor for SIC, inferred from the
   already-validated `CM_sic` notebook) — **not verified** for the config
   classes specific to VarCM/DynCM/VarDynCM/DynFM (different class names, not
   detected by the automatic substitution). Compare against the already
   working CM notebook of the same xp before a long run.
3. **Masked loss (NaN) for SIC**: the ASIP target has NaN gaps. Only the
   existing `FM_sic` implements masking (`LitFlowMatchingSIC.training_step`
   + `masked_average`). **The 6 notebooks generated for SIC do not reproduce
   it automatically** — must be added before any real training run,
   otherwise the model trains on NaN noise.
4. **`COND_MODE="grad"` / `SOLVER_TYPE="lstm"`**: explicitly forced at the
   start of the method block of every relevant generated notebook (VarCM,
   VarDynCM, 4dvarnet_lstm) — consistent with the choice made for the
   comparison, but worth confirming that the imported class actually honors
   this parameter the same way for this xp.

In short: `generate_missing_notebooks.py` produces a **structurally correct,
executable first version** (right dataloader, right method code, right log
naming), not a guarantee of physical convergence. Budget ~15 min of review
per generated notebook before a 2000-epoch run.

## Design notes

- **Why no "skip eval" during training?** The initial plan called for a
  `SKIP_EVAL` guard so that `run_training.py` computes no metrics at all.
  Implemented more simply instead: `N_SAMPLES=1` during training (near-zero
  cost, including for generative methods) rather than a cell-skipping logic
  that would be fragile to maintain across 24 heterogeneous notebooks. The
  real 50 members are only computed by `run_metrics.py`.
- **`4dvarnet_unet_spde.ipynb` covers both `UNet` and `LSTM` as the gradient
  solver** (`SOLVER_TYPE`) — a single GP source notebook for the
  `4dvarnet_lstm` method, we fix `SOLVER_TYPE="lstm"`.
- **`StochVarCM`** (syntax bug in its `LOG_DIR`, not runnable as-is) and
  **`CM_classic`** (legacy baseline, different architecture) are deliberately
  left out of the `methods.yaml` registry.
